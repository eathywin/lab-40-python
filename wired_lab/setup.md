# TCP без TLS і з TLS

Короткий скрипт `traffic.py` створює локальний приймач і клієнт, передає тестове повідомлення та завершується після підтвердження. Усе запускається на одному Kali Linux.

```bash
python3 wired_lab/traffic.py
```

Перше меню: **1** - HTTP-подібний запит, **2** - текстовий TCP/Telnet-приклад, **3** - FTP-подібні рядки USER/PASS. Друге меню: **1** - із TLS, **2** - відкритий обмін. Це короткі навчальні повідомлення для порівняння способів передавання даних.

## Перегляд у Wireshark

Вибрати інтерфейс `lo`, почати захоплення й запустити скрипт. Фільтр:

```text
tcp.port == 8080 || tcp.port == 2323 || tcp.port == 2121 || tcp.port == 8443
```

Без TLS через **Follow → TCP Stream** читається маркер `WIFI_DEMO_12345`. Після вибору TLS у записі видно встановлення TLS-з'єднання та зашифровані записи Application Data. Порт TLS у цьому стенді - 8443.

## Перевірка сертифіката

Клієнт використовує `PROTOCOL_TLS_CLIENT` і довіряє тимчасовому самопідписаному сертифікату стенда. Ім'я сервера перевіряється як `localhost`; сертифікат містить SAN для `localhost` і `127.0.0.1`.

Для перегляду збереженої перевірки відкрити `captures/sertificate_test.pcapng`:

```text
tls.handshake.extensions_server_name || tls.alert_message
```

У записі порівнюються `localhost` і `wrong_localhost`. У другому випадку клієнт надсилає fatal Bad Certificate. Помилку відповідності імені показано також на скриншоті термінала.
